  AZIONE          = cosa succede nel sistema
  CHI LA CHIAMA   = quale script Python invoca la funzione

  EVENTO EMESSO   = evento on-chain emesso (letto poi dal monitor)

════════════════════════════════════════════════════════════════════════
  PARTE 2 — SWAP ASSICURATO (il trader si protegge)
════════════════════════════════════════════════════════════════════════

  AZIONE: Calcolo preventivo premio prima di pagare
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : trader.py → ins.functions.getPremiumEstimate(val, liv)
  FUNZIONE SOL  : MEVInsurance.sol riga 1226
                  getPremiumEstimate(uint256 _swapValue,
                                     DataTypes.CoverageLevel _coverageLevel)
                  → chiama internamente PremiumCalculator.calculatePremium
  COSA FA       : view function (non modifica stato), ritorna uint256
                  Il trader la usa solo per mostrare il costo prima di pagare

  AZIONE: Calcolo premio (formula attuariale completa)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : MEVInsurance.insuredSwap() → premiumCalculator.calculatePremium()
  FUNZIONE SOL  : PremiumCalculator.sol riga 132
                  calculatePremium(uint256 _swapValue,
                                   DataTypes.CoverageLevel _coverageLevel)
  COSA FA       : applica la formula:
                    comp1 = patt * lPercent / 10000
                    comp2 = (tint * eFNR / (10000 - eFNR)) / vbase
                    comp3 = coracle24h / vbase
                    baseRate = comp1 + comp2 + comp3
                    basePremium = swapValue * baseRate / 10000
                    basePremium *= (10000 + mBase + mAdj) / 10000
                    premium = basePremium * fcov[livello] / 10000
  RITORNA       : uint256 — importo in wei da pagare in MEVI

  AZIONE: Trader paga il premio e registra lo swap assicurato
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : trader.py → ins.functions.insuredSwap(val, livello)
  FUNZIONE SOL  : MEVInsurance.sol riga 354
                  insuredSwap(uint256 _swapValue,
                              DataTypes.CoverageLevel _coverageLevel)
                  external nonReentrant
  COSA FA       : 1. chiama tierSystem.checkAndUpgrade() → aggiorna tier
                  2. verifica il trader non sia in blacklist
                  3. verifica swapValue <= maxSwapValue[tier]
                     (per Platinum: maxAllowed = stake * 10000 / alphaStakeBps)
                  4. chiama premiumCalculator.calculatePremium()
                  5. token.transferFrom(trader → contratto, premio)
                  6. crea InsuredSwap in insuredSwaps[]
                  7. incrementa profile.totalSwaps
  EVENTO        : SwapInsured(swapId, user, swapValue, premiumPaid)
  NOTA          : dopo questa tx il trader fa amm.swap() separatamente

  AZIONE: Trader esegue lo swap reale sull'AMM
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : trader.py → amm.functions.swap(usdc.address, val)
  FUNZIONE SOL  : MockAMM.sol riga 110
                  swap(address _tokenIn, uint256 _amountIn)
                  external returns (uint256 amountOut)
  COSA FA       : implementa la curva x*y=k:
                    amountOut = reserveOut * amountIn / (reserveIn + amountIn)
                  trasferisce tokenIn dal trader al contratto
                  trasferisce tokenOut (MEVI) dal contratto al trader
                  aggiorna reserveA e reserveB
  EVENTO        : Swap(sender, tokenIn, amountIn, amountOut)


════════════════════════════════════════════════════════════════════════
  PARTE 3 — ATTACCO SANDWICH (il bot attacca)
════════════════════════════════════════════════════════════════════════

  AZIONE: Bot esegue il FRONT-RUN (compra MEVI prima della vittima)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : mev_bot.py → amm.functions.swap(usdc.address, bot_amount)
                  con gasPrice = vittima_gasPrice * 1.2
  FUNZIONE SOL  : MockAMM.sol riga 110 — stessa swap()
  COSA FA       : compra MEVI con USDC
                  alza il prezzo MEVI nell'AMM (perché reserveB-USDC sale,
                  reserveA-MEVI scende)
                  → la vittima riceverà meno MEVI del previsto
  NOTA          : la tx del bot arriva PRIMA della vittima nel blocco
                  perché ha gasPrice più alto

  AZIONE: Bot esegue il BACK-RUN (rivende MEVI dopo la vittima)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : mev_bot.py → amm.functions.swap(mevi.address, bot_amount*0.99)
                  con gasPrice = vittima_gasPrice * 0.9
  FUNZIONE SOL  : MockAMM.sol riga 110 — stessa swap()
  COSA FA       : vende il 99.9% del MEVI appena comprato
                  realizza il profitto: ha comprato MEVI a prezzo basso,
                  lo rivende a prezzo (leggermente) più alto dopo il pump
                  della vittima

  NOTA IMPORTANTE — calcolo perdita prima di attaccare:
  ─────────────────────────────────────────────────────────────────────
  FUNZIONE PY   : mev_bot.py → _compute_sandwich_loss(amm, victim_amount, bot_amount)
                  (non è on-chain, è calcolo Python prima di eseguire)
  COSA FA       : legge reserveA/reserveB con amm.functions.reserveA/B().call()
                  simula la formula x*y=k due volte:
                    out_senza_attacco = MEVI che avrebbe ricevuto la vittima
                    out_con_attacco   = MEVI che riceve con frontrun
                    loss_mevi  = out_senza - out_con
                    loss_pct   = loss_mevi / out_senza * 100
                  scrive il risultato in config/attack_log.json

  PARTE 5 — COMMIT-REVEAL DEGLI ORACLE (il voto)
════════════════════════════════════════════════════════════════════════

  AZIONE: Oracle calcola il FraudScore (off-chain, in Python)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : oraclec.py → self_analyze_sandwich(...)
                  (funzione Python, non on-chain)
  COSA FA       : legge le tre tx dalla blockchain con w3.eth.get_transaction()
                  verifica pattern A-B-A (stesso blocco, indici ordinati, same from)
                  legge profilo utente: ins.functions.getUserProfile(user).call()

                    score_tier    = {Bronze:50, Silver:30, Gold:15, Platinum:0}
                    score_claim   = tabella % claim/swap
                    score_network = BFS sul grafo tx on-chain
                  total = score_tier + score_claim + score_network
                  se pattern invalido → forza total = 120
                  RITORNA (fraud_score, pattern_valid)

  AZIONE: Oracle invia il COMMIT (hash blindato del suo voto)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : oraclec.py → ins.functions.commitVerdict(claim_id, commit_hash)
  FUNZIONE SOL  : MEVInsurance.sol riga 467

  COSA FA       : verifica che msg.sender sia oracle assegnato al claim

                  verifica che il claim sia in status OracleReview
                  salva: claimCommits[claimId][oracle] = commitHash
                  incrementa claim.commitCount
  EVENTO        : VerdictCommitted(claimId, oracle)

  Come viene calcolato il commitHash in Python:
    hash = keccak256(fraud_score_uint8 || pattern_valid_bool || salt_bytes32)
    (oraclec.py riga 260 → compute_commit_hash)

  AZIONE: Oracle invia il REVEAL (svela il voto reale)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : oraclec.py → ins.functions.revealVerdict(
                    claim_id, fraud_score, pattern_valid, salt)
  FUNZIONE SOL  : MEVInsurance.sol riga 486
                  revealVerdict(uint256 _claimId, uint8 _fraudScore,
                                bool _patternValid, bytes32 _salt)
                  external
  COSA FA       : verifica msg.sender sia oracle assegnato
                  verifica non abbia già rivelato
                  verifica: keccak256(score || pattern || salt) == commit salvato
                            → se non coincide: REVERT "Hash mismatch"
                  aggiunge fraudScore a claim.revealedScores[]
                  incrementa patternValidVotes o patternInvalidVotes
                  incrementa claim.revealCount
  EVENTO        : VerdictRevealed(claimId, oracle, fraudScore, patternValid)


════════════════════════════════════════════════════════════════════════
  PARTE 6 — FINALIZZAZIONE DEL CLAIM (decisione finale)
════════════════════════════════════════════════════════════════════════

  AZIONE: Finalizzazione del claim (calcolo mediana → decisione)
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : oraclec.py → ins.functions.finalizeClaim(claim_id)
                  (può essere chiamata da chiunque, non solo oracle)
  FUNZIONE SOL  : MEVInsurance.sol riga 514
                  finalizeClaim(uint256 _claimId) external nonReentrant
  COSA FA (in ordine):

    STEP 1 — Pattern check:
      conta quanti oracle hanno votato "pattern invalido"
      se invalidi >= 70% (patternInvalidThresholdBps = 7000 bps):
        → status = InvalidPattern, fraudScore forzato a 100, FINE
      EVENTO: ClaimFinalized(claimId, InvalidPattern, 100, 0)

    STEP 2 — Calcolo mediana:
      chiama _calculateMedian(claim.revealedScores)
      (ordina l'array e prende il valore centrale)

    STEP 3 — Check dispersione:
      dispersione = max(scores) - min(scores)
      se dispersione > dispersioneThreshold (20) e non già revisione secondaria:
        → reset tutti i voti, seleziona nuovi oracle, riapre il claim
        → chiama _rewardRevealedOracles() per pagare chi aveva già votato
        EVENTO: SecondaryReviewTriggered(claimId, dispersione, newOracles[])
        FINE (claim riaperto)

    STEP 4 — Decisione per tier:
      Bronze / Silver:
        mediana <= thetaReject (80) → CAPTCHA Required
        mediana >  thetaReject (80) → Rejected + blacklist + debt 20%
      Gold / Platinum:
        mediana <  thetaApprove (60) → Approved
        mediana <= thetaReject  (80) → CAPTCHA Required
        mediana >  thetaReject  (80) → Rejected + blacklist + debt 20%

    STEP 5 — Se APPROVED: emette payout
      payout = loss * coveragePercentBps[livello] / 10000
        livello LOW    (0) → 50%
        livello MEDIUM (1) → 70%
        livello HIGH   (2) → 100%
      totalPayout = payout + gasRefundAmount (default 0.01 MEVI)
      token.transfer(user, totalPayout)
      EVENTO: PayoutIssued(claimId, user, payout)
      EVENTO: GasRefundIssued(claimId, user, gasRefundAmount)

    STEP 6 — Tracking bot (se approved):
      incrementa botAttackCount[botAddr] e botTotalDamage[botAddr]
      aggiunge bot alla blacklist dei bot noti
      EVENTO: BotBlacklisted(botAddress, attackCount, totalDamage)

    STEP 7 — Reward oracle:
      chiama _rewardRevealedOracles(claimId)
      per ogni oracle che ha rivelato:
        chiama _payOracleReward(oracle)
        trasferisce rClaim ETH (default 0.002 ETH) all'oracle
      chiama _penalizeInactiveOracles(claimId)
        penalizza chi era assegnato ma non ha rivelato
      EVENTO: OracleRewarded(oracle, amount)

    STEP 8 — Se CAPTCHA Required:
      seleziona 3 oracle speciali per la sfida captcha
      crea struct ClaimCaptcha in claimCaptchas[claimId]
      EVENTO: ClaimCaptchaRequired(claimId, user, captchaOracles[3])

  AZIONE: Calcolo mediana dei FraudScore
  ─────────────────────────────────────────────────────────────────────
  FUNZIONE SOL  : MEVInsurance.sol riga 1444
                  _calculateMedian(uint8[] storage _scores)
                  internal view returns (uint256)
  COSA FA       : insertion sort sull'array dei voti
                  se lunghezza dispari → valore centrale
                  se lunghezza pari   → media dei due centrali

  PARTE 9 — SLASHING ORACLE (penalità per disonestà)
════════════════════════════════════════════════════════════════════════

  AZIONE: Registra deviazione di un oracle dal voto mediano

  EVENTO        : OracleDeviationRecorded(oracle, newDeviationScore)

  AZIONE: Qualcuno segnala un oracle disonesto (avvia slashing formale)

  FUNZIONE SOL  : SlashingSystem.sol riga 147

  COSA FA       : richiede un deposito ETH dal reporter (reportDeposit)
                  seleziona una giuria di oracle (nJury, default 5)
                  crea Report con status Pending

  AZIONE: Giuria vota (commit-reveal) quanto slashare l'oracle accusato
  ─────────────────────────────────────────────────────────────────────
  FUNZIONE SOL  : SlashingSystem.sol riga 207
                  commitJuryVote(uint256 _reportId, bytes32 _commitHash)
                  SlashingSystem.sol riga 233
                  revealJuryVote(uint256 _reportId, uint8 _slashPercent, bytes32 _salt)
  COSA FA       : stesso meccanismo commit-reveal usato per i claim
                  slashPercent = 0-100% dello stake da confiscare

  AZIONE: Finalizzazione slashing
  ─────────────────────────────────────────────────────────────────────
  FUNZIONE SOL  : SlashingSystem.sol riga 277
                  finalizeSlashing(uint256 _reportId) external nonReentrant

                  se mediana >= thetaExpulsion:
                    chiama oracleRegistry.expelOracle(accused) → espulso
                  altrimenti:
                    chiama oracleRegistry.slashOracle(accused, amount)
                    → confisca una % dello stake
  EVENTO        : SlashingFinalized(reportId, status, slashAmount)
                  OracleSlashed(oracle, slashAmount)

  AZIONE: Penalità inattività oracle
  ─────────────────────────────────────────────────────────────────────
  CHI LA CHIAMA : MEVInsurance.finalizeClaim() → _penalizeInactiveOracles()
  FUNZIONE SOL  : OracleRegistry.sol riga 305
                  penalizeInactivity(address _oracle, uint256 _amount,
                                     address _recipient)
                  external onlyOwnerOrAuthorized
  COSA FA       : sottrae _amount dallo stake dell'oracle inattivo
                  invia la penalità al pool oracle (recipient = oracleRegistry)
  EVENTO        : OracleInactivityPenalized(oracle, amount)

  PARTE 10 — SOLVENCY RATIO E PARAMETRI FORMULA PREMIO
════════════════════════════════════════════════════════════════════════

  AZIONE: Lettura del Solvency Ratio live
  ─────────────────────────────────────────────────────────────────────

  FUNZIONE SOL  : PremiumCalculator.sol riga 184

  COSA FA       : totalLiabilities = pendingLiabilities + expectedClaims7d

                  else → poolBalance * 10000 / totalLiabilities
                  (10000 = 1.0x, 15000 = 1.5x)

  ─────────────────────────────────────────────────────────────────────
  FUNZIONE SOL  : PremiumCalculator.sol riga 231
                  updateMarketData(uint256 _tint, uint256 _vbase,
                                   uint256 _coracle24h)
  COSA FA       : aggiorna tint (frode intercettata 24h),
                            vbase (volume swap assicurati 24h),
                            coracle24h (costi oracle 24h)
                  poi chiama updateSolvencyData() per ricalcolare mAdj
  EVENTO        : MarketDataUpdated(tint, vbase, coracle24h)

  AZIONE: Aggiornamento solvency e margine adattivo
  ─────────────────────────────────────────────────────────────────────
  FUNZIONE SOL  : PremiumCalculator.sol riga 198
                  updateSolvencyData(uint256 _poolBalance,
                                     uint256 _pendingLiabilities,
                                     uint256 _expectedClaims7d)
  COSA FA       : aggiorna i dati del pool
                  calcola SR = poolBalance / (pendingLiab + expectedClaims)
                  adatta mAdj:
                    SR > srSafe     (1.5x) → mAdj  = 0      (premi normali)
                    SR > srCritical (1.3x) → mAdj  = deltaMmed (premi +5%)
                    SR <= srCritical       → mAdj  = deltaMhigh (premi +10%)
  EVENTO        : SolvencyUpdated(poolBalance, pendingLiabilities,
                                   expectedClaims7d, solvencyRatio, newMAdj)
